# DSC-V3-018: simulate retired-operator storage migration

## Objective

Use envtest to prove the accepted TrainingOperator and LlamaStackOperator
retirement behavior across a simulated v2-to-v3 CRD/storage transition. This
does not substitute for a real supported-release upgrade (Task 024).

## Required scenarios

- Start with the pre-retirement v2 storage/validation schema and a DSC whose
  retired spec and status states are both `Managed`, with unrelated spec,
  status, conditions, and metadata sentinels.
- Install the current v2/v3 CRD and conversion webhook. Read and rewrite through
  v3; verify retired fields are absent and unrelated values survive.
- Read through v2; verify both retired fields are `Removed` in spec and status.
  An unrelated v2 update must succeed; attempted re-enablement must fail.
- Keep the pre-retirement fixture explicit and isolated. Do not weaken the
  current v2 admission rules to create it.

## Verification

Run focused envtest, required Make gates, and `git diff --check`; record exact
results and any limitation of the simulated upgrade.
