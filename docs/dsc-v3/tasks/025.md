## Review 1 — 2026-09-25 11:18 UTC

[Open the CodeRabbit review conversation](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#pullrequestreview-5317005646)
(13 actionable comments).

- **Retirement CRD envtest:** After updating the CRD, wait until the API server
  rejects a disposable object with a retired field before running the
  per-field assertions. Clean up the probe if accepted. This finding targeted
  the CEL schema test, which was later removed when retirement validation moved
  to the v2 webhook; the current webhook envtests cover create and update
  rejection.
- **V3 API group documentation:** Correct the package comment in
  `api/datasciencecluster/v3/groupversion_info.go` to identify v3 and regenerate
  the API reference.
- **CSV API ownership:** Remove the retired DSC v1 owned entries from both ODH
  and RHOAI CSVs while retaining v2 and v3.
- **RHOAI init-resource defaults:** Align the init-resource annotation's AI Hub
  and Data stanzas with the v3 sample, including `data.featureStore` set to
  `Managed`; reconcile AI Gateway and `modelsAsAService` values with the chosen
  defaults so the sample consistency test passes without changing fresh-install
  behavior unintentionally. **Current status:** the annotation matches the
  RHOAI sample in this checkout; `TestInitResourceAnnotationMatchesSample`
  passes.
- **MaaS marker contract docs:** In `docs/dsc-v3/development.md` and Task 006,
  state that only a canonical MaaS `managementState` change retires the marker;
  KServe and AI Gateway parent edits preserve it. Keep `OldObject` and reserved
  metadata guidance.
- **Task 011 MaaS criteria:** Apply the same marker-retirement rule in both v3
  UPDATE criteria sections, leaving CREATE and `OldObject` requirements intact.
- **Task 011 reverse-conversion expectation:** For a marked object, require
  canonical MaaS `C=Removed` and legacy MaaS `L=Managed`, while retaining the
  migrated AI Gateway parent expectation.
- **MaaS conversion integration test:** Change a valid v3 Dashboard field,
  `standard.managementState`, instead of the pruned top-level
  `dashboard.managementState`, so the test exercises a real spec update passed
  to `AdmitMaaSV2State(old)`.
- **V1-free CRD test:** Before applying a v1-free CRD, migrate v1-stored DSCs
  through v2 and verify v1 is absent from `status.storedVersions`. If that
  prerequisite is unavailable, retain v1 in `spec.versions` with serving and
  storage disabled and update the assertion.
- **Test helper deletion semantics:** Make `testf.Delete` treat NotFound as
  success for idempotent callers, and add a strict helper for callers that need
  to detect NotFound; propagate other errors.
- **Test helper cleanup context:** In `testf.NewWithT`, preserve context values
  while preventing test cancellation from reaching cleanup callbacks. Keep
  explicit `WithContext` behavior unchanged.
- **Dashboard E2E test path:** Move the CRD-file assertion from the e2e test to
  a unit test that can locate repository sources with `FindProjectRoot`; leave
  path transformation checks in e2e.
- **Resilience E2E component counts:** Set the v3 excluded-component count to
  13, identify Data and AIHub as excluded module components, and align Tier1
  count/comments with exercised components, including DataSciencePipelines and
  Ray.
