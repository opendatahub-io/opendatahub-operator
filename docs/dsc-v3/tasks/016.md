## Accepted outcome and follow-up contract

The accepted outcome is to remove the deprecated `trainingoperator` spec and
status entries from the DSC v3 API shipped in 3.6 GA. The Jira comment records
the removal direction and requests Christoph Goern's acknowledgment; this
local decision treats the direction as recorded, while retaining that request
as evidence. Existing v2 deprecation guidance already directs users to
Trainer v2 and to retire the old TrainingOperator CR.

Keep the deprecated v2 spec/status fields for compatibility, but make v2 a
retirement-only path for the spec field:

- New v2 DSCs may omit `managementState` or set it to `Removed`; they may not
  set it to `Managed`.
- On update, an existing `Managed` value may remain `Managed` so unrelated DSC
  edits continue to work, or transition to `Removed`/empty. Empty is
  effectively `Removed` under DEC-010.
- Once the prior value is `Removed` or empty, it may not transition back to
  `Managed`.
- This rule applies to `spec.components.trainingoperator.managementState`;
  preserve the existing CEL transition guard in the generated v2 schema. The
  v2 status entry remains controller-owned. The corresponding v3 spec and
  status entries are absent.

The implemented v2 guard uses `optionalOldSelf`. The expression below is the
original decision-level form, not the literal current marker text:

```cel
!has(self.managementState) || self.managementState != 'Managed' || (has(oldSelf.managementState) && oldSelf.managementState == 'Managed')
```

The API, conversion, validation, and direct/round-trip tests were implemented
separately from this decision record. The separate Jira follow-up and link
remain outstanding; Tasks 018, 019, 021, and 024 add further migration and
cluster coverage. This decision task itself remains documentation-only.
