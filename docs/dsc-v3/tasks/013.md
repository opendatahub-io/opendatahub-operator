## Objective

Align the public Platform CR module names with DSC v3 while preserving the
existing module lifecycle and internal resource identities. Platform v1alpha1
remains served as a compatibility spoke; v1alpha2 is the conversion hub and
storage version.

## Public mapping

| Served Platform v1alpha1 | Hub/storage Platform v1alpha2 | Internal module identifier |
| --- | --- | --- |
| `spec.modules.modelregistry` | `spec.modules.aiHub` | `modelregistry` |
| `spec.modules.feastoperator` | `spec.modules.data` | `feastoperator` |

All other Platform module JSON names are unchanged. `aiHub` and `data` are
single `ManagementSpec` values in Platform; nested DSC v3 Feature Store and
Data Registry fields are not introduced here. Empty management state retains
the repository-wide effective value `Removed`.

## Implementation requirements

1. Add v1alpha2 Platform types, group version, hub marker, and generated
   deepcopy methods. Mark v1alpha2 storage and remove the v1alpha1 storage
   marker.
2. Implement explicit v1alpha1 -> v1alpha2 and v1alpha2 -> v1alpha1
   conversion. Copy object metadata, status, all unrelated module fields, and
   every management state without defaulting or cluster access.
3. Register the v1alpha1 conversion webhook and add ODH/RHOAI CRD conversion
   patches using the existing `/convert` service configuration.
4. Make Platform reconciliation, Platform CR construction, module handler
   interfaces, registry/readiness state, DSC/DSCI projection, and GVK helpers
   use v1alpha2. Keep internal handler identifiers stable.
5. Regenerate CRDs, manifests, deep-copy code, and API documentation. Verify
   both ODH and RHOAI generated artifacts contain served v1alpha1 and storage
   v1alpha2 with `aiHub` and `data` only in v1alpha2.
