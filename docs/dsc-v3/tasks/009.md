# DSC-V3-009: Implement the Data model and conversion

## Lifecycle and scope

Read `../development.md`, `../decisions.md`, `../PLAN.md`, `../TASKS.md`,
`003.md`, `005.md`, and the `006.md` Outcomes. DEC-011 preserves the internal
Data/Feast identity; DEC-012 excludes Data Connection Hub.

The implemented scope is the accepted public Data model and its v2 <-> v3
conversion. Runtime Feast/Data Registry child projection remains separate
handler work; this task does not invent that mapping.

## Existing behavior to preserve

`internal/controller/modules/feastoperator/handler.go` remains unchanged by
this model/conversion task. Its existing Feast module and external-OIDC
behavior are outside this task's scope.

## Indicative starting files

- Public types: `api/components/v1alpha1/data_types.go`,
  `api/components/v1alpha1/feastoperator_types.go`, and the versioned DSC API
  types.
- Conversion: `api/datasciencecluster/v2/datasciencecluster_conversion.go`.
- Conversion and admission coverage:
  `internal/webhook/datasciencecluster/v2/conversion/data/`.
- Webhook E2E coverage: `tests/e2e/webhooks/data_test.go`.

## Implementation

1. Define the v3 `data.featureStore` and `data.dataRegistry` model while
   preserving v2 FeastOperator names and semantics.
2. Add the v2 compatibility `dataRegistry` field under FeastOperator.
3. Implement explicit v2 -> v3 and v3 -> v2 conversion for both lifecycle
   fields, without adding defaulting or runtime projection behavior.
4. Do not add DCH or rename the internal CR, GVK, module, manifest directory,
   or metadata.

The exact spec mapping is v2 `feastoperator.managementState` to v3
`data.featureStore.managementState`, and v2
`feastoperator.dataRegistry.managementState` to v3
`data.dataRegistry.managementState`; v3-to-v2 conversion restores both paths.
These are lifecycle-only public API mappings. Runtime handler projection and
Data Registry child lifecycle/status remain deferred, so Feast runtime behavior
and the legacy FeastOperator status are not reinterpreted by this task.

## Tests

- Add direct and both round-trip v2/v3 conversion cases for both Data fields.
- Add v2 and v3 envtest admission/conversion coverage.
- Add independent real-cluster webhook E2E scenarios for v2 -> v3 and v3 -> v2 conversion.

## Required gates and definition of done

Run focused Data conversion tests and all mandatory Make gates. Complete when
the versioned Data model is generated, conversions are lossless, no runtime
projection or DCH/internal rename is introduced, and evidence is recorded.
