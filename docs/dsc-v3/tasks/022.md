# DSC-V3-022: v2 DSC Dashboard and AIHub component smoke coverage

## Objective

Add Tier3 v2-DSC smoke cases to the existing Dashboard and AIHub component
suites, included by full and targeted component E2E selection. Do not create
a separate serial compatibility suite or duplicate the full v3 lifecycle.

## Required scenarios

- Patch narrow v2 fields, read their v3 projection, verify module/component
  CR and deployment readiness plus DSC status, then read back through v2.
- Dashboard: prove independent standard and MaaS portal selection and the
  corresponding status/condition mapping.
- AIHub: prove nondefault `registriesNamespace` projects to
  `applicationNamespace` and conditions map correctly.
- Restore prior DSC values after each case; respect xKS exclusions and the
  existing parallel component-suite ownership rules.

## Verification

Run focused helper tests and E2E compilation, mandatory Make gates, and
`git diff --check`; run relevant installed-image component E2E before claiming
cluster qualification.

## Outcomes

Added Tier3 Dashboard and AIHub cases to their existing component suites.
They patch v2 fields, assert v3 projection, module CR/deployment readiness,
DSC status/conditions, and v2 readback. The Dashboard case selects portal
without the standard dashboard; the AIHub case uses a nondefault namespace.
The shared cleanup snapshots/restores only selected v2 component fields, so
parallel component suites do not overwrite each other's changes. Both cases
skip XKS as the surrounding component behavior requires.

The no-cluster cleanup helper test and top-level E2E package compilation pass;
`make generate manifests`, `make fmt`, `make lint` (0 issues), and
`git diff --check` pass. Installed-image Tier3 Dashboard/ModelRegistry
