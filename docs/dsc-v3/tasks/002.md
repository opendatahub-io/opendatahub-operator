## Existing contract and behavior

- V2 has `components.dashboard.managementState` for the core Dashboard and
  `components.dashboard.maasConsumerPortal.managementState` for the portal.
- The portal currently defaults to `Removed`; empty management state has the
  effective meaning `Removed` under DEC-010.
- `internal/controller/modules/dashboard/handler.go` enables the shared
  operator when either core or portal is managed, projects namespaces and
  gateway data, and mirrors `MaaSConsumerPortalAvailable` into DSC status.
- The accepted v3 shape is a structural `dashboard` group with independent
  `standard` and `maasPortal` children. The agreement is recorded in the
  latest RHOAIENG-94805 comment (18567363, 2026-09-22).

## Accepted contract

DEC-027 is authoritative. V3 uses:

```yaml
components:
  dashboard:
    standard:
      managementState: Managed
    maasPortal:
      managementState: Managed
```

`dashboard` is structural and has no parent management state. `standard` is
the core Dashboard; `maasPortal` is the independently managed MaaS Consumer
Portal. Both children accept `Managed` and `Removed`; empty values are
effectively `Removed` under DEC-010; the portal retains its `Removed` default;
and all four child-state combinations are valid.

The direct spec conversion is:

| V2 | V3 |
| --- | --- |
| `spec.components.dashboard.managementState` | `spec.components.dashboard.standard.managementState` |
| `spec.components.dashboard.maasConsumerPortal.managementState` | `spec.components.dashboard.maasPortal.managementState` |

Reverse conversion performs the inverse mapping. Existing status fields,
`MaaSConsumerPortalAvailable`, readiness aggregation, removal behavior, and
unrelated status/conditions are preserved. The Dashboard operator remains
enabled when either child is Managed and is removed only when both are
Removed. Existing internal Dashboard CR and module identity are unchanged;
the core and portal states retain their current CR projection.

No new CEL rule, warning, immutability rule, or parent-state conflict rule is
introduced. V2 read-modify-write preserves both independent child states.
