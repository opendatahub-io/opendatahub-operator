## Objective

Prove that an upgrade can remove v1 without ever applying a CRD that omits a
still-stored version, while keeping v2 served/deprecated and migrating storage
to v3 after the new webhook is healthy.

## Normative sequence

### Before OLM installs the new CRD

1. Run odh-cli against the installed v1/v2 CRD while the old operator and v1
   conversion webhook are healthy.
2. Read the CRD and `status.storedVersions`. Mutation-free success is allowed
   only when v1 is already absent.
3. If v1 is recorded and no DSC exists, skip object migration but patch the CRD
   status subresource to remove v1, read it back, and verify v1 is absent.
4. If v1 is recorded and the singleton exists, read/update it through v2 while
   preserving spec, status, metadata, deprecated values, and compatibility
   annotations. Verify the storage rewrite; the CRD storage marker alone is not
   evidence.
5. Only after verification, patch the CRD status subresource to remove v1,
   read it back, and require v1 to be absent.
6. Block OLM progression for unsupported sources, webhook/conversion failure,
   conflict exhaustion, preservation mismatch, failed verification, or failed
   status update. Re-running every partial state must be safe.

### After the new operator is ready

1. Verify the installed CRD contains only served deprecated v2 and storage v3,
   and `/convert` is healthy through the v2 spoke.
2. Read/update the DSC through v3, preserving the object, to force v3 storage.
3. Verify v3 appears in `status.storedVersions`; remove v2 from that status only
   after no object remains stored as v2. Continue serving v2.

### Rollback boundary

Before the v3 rewrite, rollback to the old v1/v2 release is supported. Once an
object is stored as v3, rollback requires a tested v3 -> v2 down-migration
before restoring the old CRD/operator. If that path is not shipped, the tooling
must clearly report and block rollback beyond this point.

## Required scenarios

- Fresh install with no v1.
- Supported source releases for both ODH and RHOAI, including v1 present and
  v2-only `status.storedVersions`.
- No DSC with and without v1 in `status.storedVersions`, fully populated DSC,
  already migrated state, interrupted execution at each mutation, repeated
  execution, and concurrent update conflicts.
- Old conversion webhook unavailable or returning an error; status patch
  denied/failing; verification mismatch; unsupported CRD layout.
- Preservation of spec, status, metadata, deprecated MaaS state, conditions,
  releases, related objects, and compatibility annotations.
- OLM ordering evidence that the gate completes before the v1-free CRD is
  applied.
- Successful pre-v3 rollback and tested down-migration or deliberate blocking
  after v3 storage.
