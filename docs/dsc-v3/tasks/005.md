### Representative conversion examples

These snippets show the accepted Dashboard, AI Hub, Data, and MaaS mappings.
Unshown fields and status are preserved or converted as
described in the component task records.

Dashboard keeps the same two independent lifecycle states while placing them
under version-specific names:

```yaml
# v2
spec:
  components:
    dashboard:
      managementState: Managed
      maasConsumerPortal:
        managementState: Removed
```

```yaml
# v3
spec:
  components:
    dashboard:
      standard:
        managementState: Managed
      maasPortal:
        managementState: Removed
```

AI Hub renames the public component and namespace field; conversion preserves
the namespace value in either direction:

```yaml
# v2
spec:
  components:
    modelregistry:
      managementState: Managed
      registriesNamespace: model-registry
```

```yaml
# v3
spec:
  components:
    aiHub:
      managementState: Managed
      applicationNamespace: model-registry
```

The accepted Data conversion maps both lifecycle fields directly:

```yaml
# v2 compatibility shape
spec:
  components:
    feastoperator:
      managementState: Managed
      dataRegistry:
        managementState: Removed
```

```yaml
# v3 accepted shape
spec:
  components:
    data:
      featureStore:
        managementState: Managed
      dataRegistry:
        managementState: Removed
```

For MaaS, legacy v2 `Managed` is effective only under a managed KServe parent.
When canonical v2 MaaS is `Removed`, forward conversion selects canonical v3
`Managed` and records legacy provenance; reverse conversion restores the v2
legacy source view rather than presenting the projected value as canonical:

```yaml
# v2 input
spec:
  components:
    kserve:
      managementState: Managed
      modelsAsService:
        managementState: Managed
    aigateway:
      modelsAsAService:
        managementState: Removed
```

```yaml
# v3 converted form
metadata:
  annotations:
    conversion.opendatahub.io/maas-v2-state: legacy-managed
spec:
  components:
    kserve:
      managementState: Managed
    aigateway:
      managementState: Managed
      modelsAsAService:
        managementState: Managed
```

The corresponding v2 read restores canonical MaaS to `Removed`, legacy KServe
MaaS to `Managed`, and the migrated AI Gateway parent to `Managed`. Task 012
defines marker retirement, other parent/default combinations, and the full
normalization matrix.

Shared conversion requirements remain DEC-003 and DEC-007: every changed
spec/status/condition path has direct tests in both directions, both round
trips, and an entry in the normalized OpenAPI-difference inventory. DEC-010
defines empty management state as effectively `Removed`; DEC-014 keeps evolving
v3 types version-owned and DEC-021 protects the independent v2 OpenAPI
baseline. DEC-011/DEC-012 retain internal module identities and exclude DCH.
