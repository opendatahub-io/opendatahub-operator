# DSC-V3-024: real supported-upgrade retirement E2E

## Objective

Prove retirement of the v2 TrainingOperator and LlamaStackOperator API fields
across a real supported pre-3.6-to-3.6 upgrade, for ODH and RHOAI. This is
API retirement only; no old-operand cleanup is asserted.

## Entry criteria and scenarios

- Use Task 010 and DEC-020's exact supported source releases, immutable
  artifacts, pre-upgrade gate, cluster/job matrix, and storage rewrite. Do not
  use a floating image or create a fresh 3.6 DSC with legacy `Managed` input.
- Before upgrade, prove both retired fields are `Managed` in v2 spec/status and
  save unrelated spec, status, condition, and metadata sentinels.
- After upgrade and v3 storage rewrite, prove v3 spec/status omit the fields,
  v2 spec/status show `Removed`, unrelated data survives, and a v2 update
  cannot re-enable either field.
- If the supported-source matrix or fixture cannot be provided, record the
  blocker and leave this task incomplete; do not weaken the assertion.

## Verification

Run mandatory Make gates for code changes and record installed-image ODH and
RHOAI upgrade E2E results, including the source/target artifact digests.

## Outcomes

Blocked as of 2026-09-25. Task 010 is still blocked by the externally owned
odh-cli pre-upgrade gate and proposed DEC-018 promotion control; DEC-020 has no
accepted ODH/RHOAI supported-source matrix or immutable source/target
artifacts. The local Task 018 envtest simulates v2 storage migration, and
Task 021 tests fresh-install retirement, but neither proves a supported
installed-operator upgrade. No source release, digest, job, or passing upgrade
result has been assumed. Resume only after Task 010's entry criteria are met.
