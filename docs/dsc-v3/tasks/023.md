# DSC-V3-023: v2 DSC Data and AI Gateway component smoke coverage

## Objective

Add Tier3 v2-DSC smoke cases to the existing Data/FeatureStore and AI Gateway
component suites, included by full and targeted component selection.

## Required scenarios

- Data: write v2 `feastoperator` and `dataRegistry`, verify both v3 Data
  children, FeatureStore runtime readiness, status, and v2 readback. For
  DataRegistry, assert wire mapping only where runtime projection is deferred.
- AI Gateway: write canonical v2 MaaS, verify v3 projection, module readiness,
  status, and v2 readback. Strengthen the serial conversion suite for legacy
  KServe-dependent runtime behavior; do not toggle KServe in a parallel
  component test.
- Restore prior values and apply existing xKS guards.

## Verification

Run focused local tests and E2E compilation, mandatory Make gates, and
`git diff --check`; run relevant installed-image component E2E before claiming
cluster qualification.

## Outcomes

Added Tier3 v2 DSC Data/FeatureStore and canonical AI Gateway MaaS cases to
their existing component suites. Data checks both v3 child wire projections,
FeatureStore module CR/deployment readiness, DSC status, and v2 readback;
DataRegistry remains wire-only until its runtime projection is delivered. AI
Gateway checks v3 projection, module/deployment readiness, DSC status, and
DEC-024-aware v2 readback. Both restore their original v2 fields and skip XKS.
The serial conversion suite now waits for observed MaaS status to follow the
legacy KServe-parent transition; no KServe toggle was added to parallel tests.

Both affected E2E packages compile and focused no-cluster tests pass.
`make generate manifests`, `make fmt`, `make lint` (0 issues), and
`git diff --check` pass. Installed-image Tier3 FeastOperator/AIGateway and
serial conversion DSC jobs are still required. `make api-docs` is deferred
because `docs/api-overview.md` contains pre-existing user changes.
